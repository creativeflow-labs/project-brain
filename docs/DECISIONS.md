# Project Brain 주요 결정 기록

## ADR-001: Notion 인증 단계화

- 기록일: 2026-07-25
- 상태: ADR-002로 대체
- 담당: Project Brain 개발

### 현재 결정

사내 MVP와 기능 검증 단계에서는 Notion `액세스 토큰` 방식을 사용한다.

- 대상: 단일 사내 Notion 워크스페이스
- 목적: Notion 수집 → RAG 검색 → 네이버웍스 질의응답 흐름의 정확도와 안정성 검증
- 현재 구현: 사용자가 Project Brain 화면에 액세스 토큰과 페이지 URL을 입력해 문서를 가져온다.
- 제한: 토큰을 영구 저장하지 않으며, 자동 동기화와 고객용 연결 UX는 아직 제공하지 않는다.

### OAuth 전환 조건

다음 중 하나를 시작하기 전에 Notion OAuth 2.0 연결을 구현한다.

- 외부 고객 대상 파일럿
- 여러 고객사 또는 여러 Notion 워크스페이스 지원
- 사용자가 토큰을 직접 복사하지 않는 정식 연결 경험
- 주기적 자동 동기화

### OAuth 고도화 필수 항목

- Notion 공개 연결과 OAuth 콜백 구현
- CSRF 방지를 위한 `state` 검증
- 워크스페이스별 액세스 토큰·리프레시 토큰 암호화 저장
- 토큰 갱신, 만료, 폐기 및 재연결 처리
- 연결할 페이지 선택과 최소 권한 적용
- 고객사별 데이터·토큰 격리
- 연결 상태, 마지막 동기화 시각, 오류 이력 표시
- 자동 동기화 스케줄러와 재시도 정책
- 연결 해제 시 토큰 및 동기화 데이터 처리 정책
- OAuth 성공·실패·갱신·해제 통합 테스트

### 유지 원칙

액세스 토큰 방식은 사내 개발과 장애 진단용으로 유지하되, 외부 고객이 사용하는 운영 환경의 기본 인증 방식으로 제공하지 않는다.

## ADR-002: Notion 지식공간 자동 동기화

- 기록일: 2026-07-25
- 상태: 확정
- 적용 버전: v0.2.0

### 문제 정의

페이지 URL을 사용자가 매번 입력하거나 Notion 페이지 위계를 Project Brain에 맞춰 재구성하게 하면 변동성이 큰 조직 지식을 안정적으로 운영할 수 없다. 제품이 기존 지식 구조를 흡수해야 하며, 사용자의 Notion 운영 방식을 강제하지 않는다.

### 결정

- 페이지 URL 입력을 기본 사용자 흐름에서 제거한다.
- 사내 단일 계정 검증은 개인 액세스 토큰(PAT)으로 접근 가능한 범위를 자동 탐색한다.
- 내부 연결 토큰도 지원하되, 명시적으로 공유된 범위만 동기화한다.
- 외부 고객 파일럿 전에는 OAuth로 전환한다.
- 토큰은 프로젝트별로 암호화 저장한다.
- 최초 전체 탐색 이후 수정 시각과 콘텐츠 해시를 이용해 증분 동기화한다.
- 자동 동기화와 수동 전체 재검사를 함께 제공한다.

### 완전성 경계

Notion Search API는 접근 가능한 모든 문서의 완전한 열거를 보장하지 않는다. 따라서 PAT 기반 계정 탐색은 `최선 노력`으로 표시하고, 제품에서 `워크스페이스 전체 100% 수집`을 약속하지 않는다. OAuth 제품에서는 사용자가 승인한 범위를 기준으로 동기화 상태와 누락 가능성을 명시한다.

### 안정성 원칙

- 페이지 하나의 실패가 전체 동기화를 중단하지 않도록 격리한다.
- API 속도 제한과 일시 장애에 재시도·지수 백오프를 적용한다.
- 동시 중복 동기화를 프로젝트 단위로 차단한다.
- 검색 누락만으로 기존 문서를 삭제하지 않는다.
- API가 삭제·보관·권한 회수를 확인한 경우에만 인덱스를 제거한다.
- 외부 URL 첨부는 자동 다운로드하지 않고 Notion이 호스팅한 지원 파일만 처리한다.
- 토큰·암호화 키·`.env`는 Git 및 Docker 이미지에 포함하지 않는다.
