# 검색 정확도 검토본 · v0.3.1-rc.1

> 2026-10-16 사용자 검토 후 `v0.3.1` 정식 배포를 승인했습니다. 아래는 당시 검토 과정과 한계를 보존한 기록입니다. 기능 추가 없이 버전 표기를 정식 버전으로 전환했습니다. 일반 질문의 속도 개선이나 모든 질문의 정확도 합격을 의미하지 않습니다.

## 범위

공식 배포 전 사용자 검토본입니다. 기존 Notion 계층·전체 목록·대화 문맥·근거 스냅샷·일반 LLM 판정·상태 엔진을 유지했습니다. 모델 교체, 재임베딩, DB 스키마·인덱스 변경은 하지 않았습니다.

로컬 검토 이미지는 `Dockerfile.review`로 보존한 기존 실행 이미지 위에 코드만 반영합니다. 일반 Dockerfile의 최신 기반 이미지/패키지 재설치가 검토 환경에 섞이지 않도록 기존 의존성을 유지합니다. 이 파일은 현재 호스트용이며 정식 배포 Dockerfile을 대체하지 않습니다.

변경은 개별 커밋으로 구분합니다.

1. 한국어 lexical 후보 보충: 기존 키워드 검색 결과가 0건일 때만 접두 일치로 보충합니다. 결과가 있는 검색은 기존 SQL·후보·정렬을 유지합니다. 영문 ID는 접두 일치를 적용하지 않습니다. 프로젝트 경계와 후보 한도를 유지합니다. 완전한 한국어 형태소 분석기는 아닙니다.
2. 추출형 금액 판정 안전장치: 모델 사용이 불가능할 때 쓰는 대체 경로에서 제안·견적·기록을 최종 합의로 확정하지 않습니다. 일반 모델 답변에 대한 새 판정 알고리즘은 아닙니다.
3. 제품 정체성 응답: 명확한 이름 질문만 제품 정보로 응답하고 무관한 프로젝트 자료 검색을 생략합니다. 업무·복합 질문은 기존 경로를 사용합니다.

## 비교 방법과 해석 경계

- 사용자가 제공한 13개 질문으로 기준본 1회, 초기안 1회, 비용 가드를 좁힌 최종안 1회를 같은 순서로 실행했습니다. 실행마다 새 대화에서 시작하고 후속 질문의 thread를 유지했습니다. 개선안 검토는 별도 로컬 서버에서 수행했습니다.
- 두 환경은 같은 데이터베이스와 모델 설정을 사용합니다. 별도 검토 서버와 기존 서버의 프로세스 캐시는 다르며, 일부 실행 중 DB 진단 부하도 있었습니다. 시간 차이는 성능 개선률이나 정식 벤치마크가 아닙니다.
- 초기 후보 보충안은 고정한 이전 검색 계획 7건의 lexical 후보를 별도 읽기 전용으로 재생했을 때 기존 후보 유실은 0건이었습니다. 그러나 일반 질문의 비용 증가 가능성이 보여, 최종안에서는 보충을 0건 검색으로만 제한했습니다. 초기 비교 파일은 진단 이력이며 최종안의 성능 근거가 아닙니다.
- 전체 목록 사례의 답변 본문과 인용 문서 집합은 전후 동일했습니다.
- 제품 이름 질문은 이전의 근거 부족 응답에서 제품 정보 응답으로 바뀌었으며 사내 자료 인용은 0건입니다.
- 오타 정정 연속 질문은 내용상 관련 정보를 제공했으나 supported에서 insufficient로 판정 상태가 달라졌습니다. 단순한 상태값 비교로 회귀/개선을 확정하지 않으며 사용자 검토 대상으로 남깁니다. 고정 계획 lexical 비교에서는 해당 두 질문의 후보 집합이 동일했습니다.
- 의사결정자 근거가 불충분한 질문은 확인 불가 응답을 유지합니다. 원문에 정답이 없다고 확정한 것은 아닙니다.
- 실제 질문·응답·자료명은 `data/accuracy-review/20261016/`에만 보존하고 Git·Docker 빌드에서 제외합니다. `baseline.json`은 이전 버전, `updated.json`과 `comparison.md`는 초기안, `final.json`과 `final-comparison.md`는 최종 검토본 비교입니다.
- 모든 API 응답 성공이나 단위 테스트 통과를 사실 정확도 100%로 표현하지 않습니다. 정식 승인은 사용자 검토 후 진행합니다.

실행 환경만 즉시 복원하는 명령은 다음과 같습니다. 현재 검토 코드는 Git에 보존됩니다.

```sh

docker compose up -d --no-build --no-deps app
```

검토 단계에서는 정식 릴리스 태그 생성, main 반영, 원격 업로드를 보류했습니다. 사용자 승인 후 정식 릴리스 절차로 진행합니다.

- 자동 테스트: 67개 통과. 실제 모델의 사실 정확도 합격 점수와는 별개입니다.
- 최종 13개 API 질문은 모두 응답했고, 답변의 인용 번호가 범위를 벗어나지 않았습니다.
- 전체 목록은 16건 및 원문 문서 집합을 유지했습니다. 제품 이름 질문은 프로젝트 인용 없이 응답했습니다.
