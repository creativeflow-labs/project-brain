# 로컬 검색 성능 개선 검토 (2026-10-16)

> 사용자 실사용 검토 및 승인 후 `v0.3.2` 정식 릴리스에 포함했습니다.

아래는 정식 배포 전에 수행한 로컬 비교 기록입니다.
직전에 승인받은 영상 조건 검색·집계 수정은 그대로 유지합니다.

## 확인된 병목과 변경 범위

- PostgreSQL 키워드 후보 검색이 검색어마다 제목·메타데이터·본문을
  `to_tsvector`로 다시 변환했습니다. 계층 메타데이터도 이 처리에 포함됩니다.
- 여러 검색어가 있는 bounded hybrid/one 경로에서만, 요청 내부의
  `MATERIALIZED` CTE로 동일한 변환 결과를 공유합니다.
- 검색 대상 문자열, 프로젝트 범위, 검색어별 후보 상한·동점 정렬,
  정확 검색이 0건일 때만 실행하는 한국어 prefix 보완을 유지합니다.
- 벡터 검색, 계층 점수, 근거 확장, 답변 생성, 전체 자료/컬렉션 경로는 변경하지 않습니다.
- DB 스키마·색인·원문·동기화는 변경하지 않습니다. 요청 사이 캐시도 추가하지 않습니다.

## 동일 조건 비교

저장된 실제 검색 계획과 임베딩을 고정하고 변경 전후를 순차 실행했습니다.
각 2회 검색 단계의 중앙값이며, 임베딩 API 및 LLM 계획·답변 생성 시간은 제외했습니다.

| 질문 | 이전 | 변경 후 |
| --- | ---: | ---: |
| 김그륜 바이브코딩 | 6.675초 | 1.360초 |
| SK 다이렉트 의사결정자 | 7.026초 | 1.184초 |
| AI 웨비나 전체 자료 | 3.910초 | 3.817초 |
| 6월 영상 목록 | 1.265초 | 1.292초 |

앞의 두 경로에서 약 80~83% 단축되었습니다. 뒤의 두 경로는 변경 대상이 아니며
수치 차이는 작은 실행 편차입니다. 답변 표시까지의 전체 시간이 같은 비율로 줄어든다는 뜻은 아닙니다.

## 결과 보존 확인

- 네 질문의 후보 순서·계층 점수·근거 본문 해시가 동일했습니다.
- 종합 점수 차이는 최대 약 `1.1e-16`이었습니다. 변경하지 않은 전체 자료 경로에서도
  나타나는 프로세스별 BM25 토큰 집합 순회 순서에 따른 부동소수점 차이입니다.
  비교기는 순서·계층 점수·근거는 정확 일치, 종합 점수는 절대 오차 `1e-12` 이하를 요구합니다.
- 별도 PostgreSQL 읽기 전용 비교 3건에서 기존 단일 검색들의 합집합과 새 일괄 검색의
  전체 키워드 후보 ID·순서가 일치했습니다. 한국어 prefix 보완·결과 없음·영문 검색을 포함합니다.
- 자동 테스트 71개 통과. 실제 데이터 비교에서는 DB 기록을 변경하거나 답변 모델을 호출하지 않았습니다.
- 재현 도구: `scripts/review_search_performance.py`.
  질문·임베딩·비교 원본은 Git에서 제외한 `data/performance-review/`에 보관합니다.

## 남은 범위

전체 자료를 불러오는 경로와 LLM 답변 작성 지연은 이번 변경으로 해결되지 않습니다.
계층 도입 전 데이터와의 완전한 역사적 비교가 아니라, 현재 데이터에서 확인한 병목을 제거한 작업입니다.

이후 성능 개선은 질문 전송부터 최종 답변이 화면에 표시될 때까지의 시간을 주 평가 기준으로
측정합니다. 서버 처리시간과 실제 화면 노출시간을 구분하고 내부 단계별 시간은 원인 분석에 사용합니다.
