# Project Brain 제품 로드맵

이 문서는 장기 프로젝트에서 기능 누락을 방지하기 위한 제품 로드맵이다. 확정된 설계 원칙은 [DECISIONS.md](DECISIONS.md), 출시별 변경 사항은 [CHANGELOG.md](../CHANGELOG.md)에서 관리한다.

## 제품 정의

Project Brain은 흩어진 프로젝트 기록을 연결해 무엇이 왜 결정됐고, 현재 누가 무엇을 해야 하는지 원문 근거와 함께 답하는 팀용 AI 브레인이다.

핵심 경험:

> 딱 우리 팀 정보이고, 우리 팀 프로세스다.

## 단계별 로드맵

### 1단계: 지식 데이터 연결

- [x] 일반 업로드 PDF·DOCX·TXT·MD
- [x] Notion 접근 범위 발견과 증분 동기화
- [ ] Gmail OAuth 연결 및 본문·스레드·첨부파일 동기화 실사용 검증
- [ ] Google Drive 연결
- [ ] 연결 상태, 마지막 동기화, 실패 항목, 재시도 상태 통합 표시
- [ ] 출처별 외부 원본 식별자와 중복 자료 관리

완료 기준:

- 각 출처가 서로 덮어쓰거나 섞이지 않는다.
- 변경·삭제·권한 회수가 예측 가능하게 반영된다.
- 모든 검색 근거에서 원본을 열 수 있다.

### 2단계: 출처 제어형 다중 검색

- [ ] 검색 범위 UI: 전체·Notion·Gmail·Drive·업로드
- [ ] 복수 출처 선택
- [ ] 검색 범위를 후속 질문에 유지
- [ ] 같은 질문을 단일 출처와 전체에서 비교하는 회귀 테스트
- [ ] 최신 정보와 과거 정보 충돌 감지
- [ ] 공식 문서, 대화, 초안의 성격 구분
- [ ] 중복 문서와 이메일 답장 인용 제거
- [ ] 전체 검색의 출처별 결과 수 균형 조정
- [ ] 답변 전 근거 충분성 검증

완료 기준:

- 사용자가 지정한 출처 밖의 자료가 답변 근거에 포함되지 않는다.
- 전체 검색에서 충돌을 숨기지 않고 출처와 시점을 설명한다.
- 검색 결과가 늘어나도 핵심 프로젝트 식별자와 최신 결정의 정확도가 유지된다.

### 3단계: 프로젝트 시간축

- [ ] Google Calendar 읽기 전용 연결
- [ ] 필요 시 팀이 사용하는 다른 Calendar 연결 검토
- [ ] 일정·회의·마감과 프로젝트 문서·메일 연결
- [ ] 일정 변경 이력과 발생 시점 보존
- [ ] 회의 전 관련 문서·메일·미완료 업무 요약

대표 질문:

- 이번 주 마감은 무엇인가?
- 내일 회의 전에 확인해야 할 내용은 무엇인가?
- 일정 변경의 이유와 관련 대화는 어디에 있는가?

### 4단계: 팀 워크플로우

- [ ] 첫 고객군이 실제 사용하는 업무관리 서비스 선정
- [ ] 업무·담당자·상태·우선순위·의존 관계 읽기
- [ ] 프로젝트·업무·일정·결정·승인 공통 모델 구축
- [ ] 이메일과 문서의 결정이 실제 업무 상태에 반영됐는지 검증
- [ ] 지연 요인, 승인 대기, 담당자 공백 감지

대표 질문:

- 지금 이 프로젝트를 막고 있는 것은 무엇인가?
- 다음 행동은 무엇이고 담당자는 누구인가?
- 문서에서 확정된 결정이 업무관리 서비스에 반영됐는가?

### 5단계: 승인 기반 실행

- [ ] 일정 생성·변경
- [ ] 업무 생성·담당자 지정·상태 변경
- [ ] 메신저 알림과 승인 요청
- [ ] 실행 전 변경 대상·내용·영향 범위 미리보기
- [ ] 명시적 승인, 감사 로그, 실패 복구

원칙:

- 읽기 기능을 먼저 안정화한다.
- 쓰기 기능은 기본적으로 승인 없이는 실행하지 않는다.
- 검색 오류가 실제 업무 변경으로 이어지지 않도록 검색·판단·실행 계층을 분리한다.

## 장기 데이터 모델

향후 연결과 검색을 위해 다음 개념을 공통 모델에서 관리한다.

- 프로젝트
- 데이터 출처와 연결 계정
- 문서·메일·스레드·첨부파일
- 일정·회의·마감
- 업무·담당자·상태·우선순위
- 결정·변경 이유·승인
- 의존 관계
- 발생 시점·수정 시점·유효 시점
- 원문 위치와 접근권한

## 개발 우선순위 원칙

1. 데이터 연결 안정성
2. 출처 분리와 원문 추적
3. 다중 출처 검색 정확도
4. 충돌·최신성·공식성 판단
5. Calendar와 업무 흐름 이해
6. 사용자 승인 기반 실행

새 기능은 현재 단계의 완료 기준을 검증한 뒤 다음 단계로 이동한다.
